Tech Stack for Monorepo SaaS Architecture

AI-friendly tech stack optimized for code generation and a monorepo with three distinct services.

Website Marketing

Framework: Next.js (App Router)

Why: React is AI-friendly, built-in routing/auth, file-based structure

Styling: Tailwind CSS + shadcn/ui

Static/Edge: Vercel Edge for fast global delivery

AI Advantage Predictable component structure = better code generation

Operator Control Plane

Backend: Node.js (Express/Fastify)

Why: Shared language, async-first, rich ecosystem

Database: PostgreSQL + Redis

Admin UI: Next.js (same as website)

AI Advantage Monorepo shares models, migrations, utilities

Tenant Product

Frontend: Next.js (App Router)

Why: Isomorphic, easy to customize per tenant

Backend: Shared Node.js API

Styling: Tailwind + CSS-in-JS (emotion/styled-components)

AI Advantage Component-driven = AI can generate features incrementally

Monorepo Setup

Option A: Turborepo (Recommended)

  • ✓ Fast, simple, minimal config
  • ✓ Great caching (local + cloud)
  • ✓ Perfect for Next.js apps
  • Smaller community

Option B: Nx

  • ✓ More powerful plugins
  • ✓ Better code generation
  • ✓ Dependency analysis
  • Steeper learning curve

Shared Infrastructure (All Apps)

Auth NextAuth.js / Auth0 (shared session logic across apps)
API TypeScript (tRPC or OpenAPI for shared types)
DB Prisma ORM (schema-driven, migrations, seed scripts)
Testing Vitest + Playwright (fast, parallel, AI-testable)

Prisma Schema (Shared Database with RLS)

Single PostgreSQL for all tenants. Row-level security enforced at the database layer.

// ==================== TENANT ISOLATION (RLS) ====================
// All queries filtered by office_id via PostgreSQL RLS policies
// Schema designed for office-level data isolation

// ==================== CORE ORGANIZATION ====================
model Organization {{
  id        String   @id @default(cuid())
  name      String
  email     String   @unique
  website   String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  offices   Office[]
  billing   Billing?

  @@index([email])
}}

model Office {{
  id              String   @id @default(cuid())
  organizationId  String
  name            String
  address         String
  city            String
  state           String
  zipCode         String
  country         String @default("India")
  isOwned         Boolean  // true = owned, false = rented
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt

  organization    Organization @relation(fields: [organizationId], references: [id], onDelete: Cascade)

  // Core relations
  users           OfficeUser[]
  utilities       UtilityConnection[]
  lease           Lease?
  landlord        Landlord?
  bills           Bill[]
  compliance      ComplianceInstance[]
  assets          Asset[]
  facilities      Facility[]
  vendors         Vendor[]
  workflows       Workflow[]

  @@unique([organizationId, name])
  @@index([organizationId])
}}

// ==================== USERS & ROLES ====================
model User {{
  id            String    @id @default(cuid())
  email         String    @unique
  name          String?
  password      String?   // hashed, null if OAuth
  emailVerified DateTime?
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt

  // Auth relations
  accounts      Account[]
  sessions      Session[]
  officeUsers   OfficeUser[]
  invites       UserInvite[]
  workflowSteps Workflow[]

  @@index([email])
}}

model OfficeUser {{
  id        String   @id @default(cuid())
  userId    String
  officeId  String
  role      Role     // ADMIN, CHECKER, AUTHORIZER, COMPLIANCE, VENDOR_MGR, FACILITY_STAFF
  createdAt DateTime @default(now())

  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  office    Office   @relation(fields: [officeId], references: [id], onDelete: Cascade)

  @@unique([userId, officeId])
  @@index([officeId])
}}

enum Role {{
  ADMIN
  CHECKER
  AUTHORIZER
  COMPLIANCE
  VENDOR_MGR
  FACILITY_STAFF
}}

model UserInvite {{
  id        String   @id @default(cuid())
  email     String
  officeId  String
  role      Role
  token     String   @unique
  expiresAt DateTime
  userId    String?  // populated after user signs up
  createdAt DateTime @default(now())

  user      User?    @relation(fields: [userId], references: [id], onDelete: SetNull)
}}

// ==================== UTILITIES ====================
model UtilityConnection {{
  id         String   @id @default(cuid())
  officeId   String
  type       String   // ELECTRICITY, WATER, GAS, INTERNET, etc
  provider   String   // BSNL, Airtel, etc
  accountNum String
  meterNum   String?
  billingCycle Int // day of month
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt

  office     Office   @relation(fields: [officeId], references: [id], onDelete: Cascade)
  bills      Bill[]

  @@unique([officeId, type, provider])
  @@index([officeId])
}}

model Bill {{
  id                String   @id @default(cuid())
  officeId          String
  utilityId         String
  amount            Decimal
  dueDate           DateTime
  invoiceNum        String?
  status            WorkflowStatus // DRAFT, PENDING, APPROVED, REJECTED, PAID
  madeBy            String   // userId of maker
  checkedBy         String?  // userId of checker
  authorizedBy      String?  // userId of authorizer
  remarks           String?
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt

  office            Office   @relation(fields: [officeId], references: [id], onDelete: Cascade)
  utility           UtilityConnection @relation(fields: [utilityId], references: [id], onDelete: Cascade)
  payments          Payment[]
  workflows         Workflow[]

  @@index([officeId, status])
  @@index([dueDate])
}}

model Payment {{
  id        String   @id @default(cuid())

  amount    Decimal

  date      DateTime
  refNum    String?  // reference number
  createdAt DateTime @default(now())

  bill      Bill     @relation(fields: [billId], references: [id], onDelete: Cascade)

  @@index([billId])
}}

// ==================== COMPLIANCE ====================
model ComplianceType {{
  id        String   @id @default(cuid())
  name      String   @unique  // Trade Licence, Fire NOC, etc
  category  String   // LEGAL, SAFETY, ENVIRONMENTAL

  instances ComplianceInstance[]
}}

model ComplianceInstance {{
  id             String   @id @default(cuid())
  officeId       String
  typeId         String
  certificateNum String?
  issueDate      DateTime
  expiryDate     DateTime
  status         String   // VALID, EXPIRING_SOON, EXPIRED
  documentUrl    String?  // uploaded cert
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt

  office         Office         @relation(fields: [officeId], references: [id], onDelete: Cascade)
  type           ComplianceType @relation(fields: [typeId], references: [id])

  @@unique([officeId, typeId])
  @@index([officeId, expiryDate])

// ==================== ASSETS ====================
model Asset {{
  id         String   @id @default(cuid())
  officeId   String
  name       String
  category   String   // IT, FURNITURE, EQUIPMENT, FIXED_ASSET
  location   String?
  custodian  String?  // userId or name
  purchaseDate DateTime?
  value      Decimal?
  warrantyEnd DateTime?
  status     String   // ACTIVE, RETIRED, DAMAGED
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt

  office     Office   @relation(fields: [officeId], references: [id], onDelete: Cascade)
  requests   AssetRequest[]

  @@index([officeId, status])
}}

model AssetRequest {{
  id        String   @id @default(cuid())
  officeId  String
  requestedBy String // userId
  assetId   String?  // if requesting existing asset
  category  String   // if new asset needed
  description String
  status    String   // PENDING, APPROVED, ALLOCATED
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  asset     Asset?   @relation(fields: [assetId], references: [id])

  @@index([officeId, status])
}}

// ==================== FACILITIES ====================
model Facility {{
  id        String   @id @default(cuid())
  officeId  String
  name      String   // Cleaning, AC, DG, UPS, etc
  owner     String?  // custodian name/id
  lastMaint DateTime?
  createdAt DateTime @default(now())

  office    Office   @relation(fields: [officeId], references: [id], onDelete: Cascade)
  requests  MaintenanceRequest[]

  @@unique([officeId, name])
  @@index([officeId])
}}

model MaintenanceRequest {{
  id          String   @id @default(cuid())
  facilityId  String
  officeId    String
  reportedBy  String   // userId
  description String
  status      String   // OPEN, IN_PROGRESS, COMPLETED

  completedAt DateTime?

  vendor      Vendor?  @relation(fields: [vendorId], references: [id])
  evidence    MaintenanceEvidence[]

  @@index([officeId, status])
  @@index([slaDueDate])

// ==================== WORKFLOWS & APPROVALS ====================

Master Data Checklist Pattern (UX Optimization)

Replace free-form text with predefined master lists. Users checkmark → System batch-creates records. Faster, consistent, queryable.

✓ Utilities

Master list: ELECTRICITY, WATER, GAS, INTERNET, TELEPHONE, DG, UPS, SOLAR

Flow: Checkboxes → Select utilities → Specify provider + meter → Submit → System creates UtilityConnection records

Reduces entry friction, prevents typos, enables fast filtering in dashboards

✓ Facilities

Master list: CLEANING, AC/HVAC, DG, UPS, GENERATOR, BUILDING_MAINTENANCE

Flow: Checkboxes → Select facilities → Assign owner → Submit → Facility register auto-populated

✓ Compliance Types

Hardcoded for India: TRADE_LICENCE, FIRE_NOC, ELECTRICAL_SAFETY, LIFT, POLLUTION

Flow: Checkboxes → Mark applicable certifications → System tracks expiry dates

✓ Vendor Categories

Master list: MAINTENANCE, CLEANING, IT_SUPPORT, ELECTRICAL, HVAC, PLUMBING

Flow: Vendor profile → Select category → Checkboxes for facilities served

Implementation: Add *Type models (UtilityType, FacilityType, VendorCategory) to Prisma schema. Cycle 1 adds static seed data. Cycle 2 builds UI with checkboxes + batch create endpoints.

Benefits: Faster data entry (no typing), data consistency, better reporting & analytics, reduced admin overhead.

Wizard-Based Forms (Multi-Step)

Large forms split into logical steps. Each step = one topic group.

✓ Office Onboarding Wizard (Cycle 1): Org details → Owned/Rented? → Setup Readiness → Invite team

✓ Utility Setup Wizard (Cycle 2): Select utilities (checkboxes) → Provider details → Confirm & Save

✓ Lease Setup Wizard (Cycle 3): Owned/Rented → Landlord → Lease terms → Review

✓ Bill Approval (All cycles): Separate modal (focused UX, not in main form)

Cognitive Load Principles

  • ✓ Group by domain (Utilities → Bills → Approvals → Payments)
  • ✓ Progressive disclosure (Wizard reveals fields step-by-step)
  • ✓ Consistent patterns (Same wizard style everywhere)
  • ✓ Clear navigation (Persistent left sidebar, no context-switching)
  • ✓ Avoid overwhelm (Never show 20 fields at once)

Implementation: Build navbar structure + Wizard components in Cycle 1. Subsequent cycles add content within established sections (no restructuring).
